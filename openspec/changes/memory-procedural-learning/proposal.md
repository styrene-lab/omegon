# Evidence-backed procedural memory — Wave 8

## Intent

Retain scoped workflows and environment gotchas with evidence of actual application.
Distinguish retrieval, execution, completion, and verified task success so later
sessions can avoid repeated errors without learning unsupported generalizations.

This is a post-Wave 5 plan assessed against `main` at `7b2da402`. All Wave 8
behavior below is planned. See [assessment.md](assessment.md) for current owners,
drift findings, dependencies, and unknowns.

## Scope

- Stable procedure identities with immutable versions, scoped hypotheses,
  evidenced guidance, counterexamples, retirement, and inspectable history.
- Separate application identities and source-bound, versioned outcome feedback.
- Applicability-aware selection through the existing memory selector, budget,
  cache, and skills disclosure owners.
- Explicit operator promotion through a frozen shared plan/apply/inspect/result
  contract, strict skills-owner diagnostics, and recoverable guarded writes.
- First slice: prompt-only `SKILL.md` at a new project-local destination.
- Application, negative-transfer, and held-out-environment evaluation fixtures.

Replacement, user/global installation, executable asset import, automatic
promotion, and activation bypasses are excluded from this slice. Existing skills
parsing, provenance, activation, disclosure, create/import/reload, and guarded
project writes are reused and extended where required. No second skills engine,
installer, or context injector is introduced.

## Dependencies and sequencing

Wave 5 is accepted infrastructure and smoke evidence. Accepted Wave 6
reconciliation is required before automatic procedure admission or correction.
Wave 8 requires only the explicit Wave 7 policy contract for evidence versus
usage, verification/validity/retention, unknown-source preservation, and versioned
feedback. The whole Wave 7 scheduler is not a prerequisite.

Freeze procedure/application contracts, promotion approval semantics, and shared
surface DTOs before parallel host integration. Fixture and detailed design work
can proceed in parallel after those interfaces freeze.

## Success criteria

- Tool success, duplicate imports, and selection without execution cannot become
  verified workflow success or independent application evidence.
- Missing sources, truncation, unknown required tool versions, and failed
  verification remain explicit and affect eligibility.
- Selection accounts for the complete guidance unit and deduplicates promoted
  skills without changing runtime authority.
- Promotion binds operator approval to exact plan bytes and preconditions, rejects
  malformed artifacts, preserves human edits, and recovers from interrupted writes.
- TUI, CLI remote, and ACP expose the same promotion result semantics through a
  registered surface, with explicit unavailable results where execution is unsupported.
- New evaluation measures actual applications and repeated-error opportunities,
  with stage attribution and held-out environments. Live evaluation requires a
  fresh authorized model budget and thresholds frozen before held-out runs.
